# Entropy on Classic Mac OS

Date: 2026-10-31.

## Sources

- https://github.com/mplsllc/macTLS (README, fetched): macEntropy section
- https://github.com/mplsllc/macTLS `MACENTROPY_SCOPE.md` (referenced; not
  fetched)
- https://bearssl.org/ (HMAC-DRBG; TLS 1.2 only)
- https://github.com/yllan/ClassicNet `SECURITY.md` (referenced in its README;
  its earlier note that base entropy is weak)
- Wolfram `src/transport/macos9_tls.c` (local)

## Findings

- Classic Mac OS has no hardware RNG. Earlier project notes treated that as
  fatal for TLS. macTLS's current documentation claims a production seeding
  subsystem, `macEntropy`: a SHA-256 pool fed by timer jitter, mouse movement,
  stack noise, packet-arrival timing and optional live input, with domain
  separation, a Preferences seed file carried across reboots, and an
  HMAC-DRBG. It says the seed stream is different on every launch and the
  subsystem was hardware-validated on a G3 in May 2026.
- That is materially better evidence than "no entropy source". It is still a
  vendor claim about a specific macTLS revision, not an independent audit, and
  it is not obviously wired into the Wolfram transport Platinum links.
- DPoP needs a long-lived P-256 private key. Even a good TLS handshake seed does
  not solve key storage, key backup and the consequence of a weak or cloned
  key. Those remain separate problems.

## Decision impact

- Revise ADR 0005. The blocker is no longer "there is no entropy source"; it is:
  1. Platinum must build against a macTLS revision that contains macEntropy and
     TLS 1.3.
  2. The seeding path must be exercised on real PowerPC hardware (the
     `kOSTLSAsync_EntropyFail` path must never be bypassed).
  3. DPoP key generation and storage need their own design; macEntropy alone
     does not authorise it.
  4. No DPoP/OAuth code until 1-3 are done and independently reviewed.
- TLS 1.2/1.3 with a verified chain is still usable for phase 1 app-password
  sessions. That does not require long-lived keys.

## Not verified

- The actual quality of macEntropy on a 68k or G3/G4 with a cold boot and no
  mouse input. No hardware here.
- The seed file's protection: it lives in Preferences, like every other
  classic-Mac file.
- Whether Wolfram's pinned CI transport exposes or initialises macEntropy at
  all. The local transport calls `OSTLS_*` and only reports its error code.
