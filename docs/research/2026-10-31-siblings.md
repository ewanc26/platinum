## Wolfram

Wolfram is the single implementation of three things Platinum was preparing to
write itself:

1. **Muted words.** `wf_muted_words_match` and `wf_muted_list_*` implement the
   lexicon's `mutedWord` rules: content and tag targets, `exclude-following`,
   `expiresAt` judged at a caller-supplied `now` (0 means the clock is unknown
   and nothing expires), and the official matcher's word-boundary rules.
   `wf_mod_match_mute_words` in `moderation.h` is the underlying matcher.
   **But** the headers require C99 (`stdbool.h`, `stdint.h`, `bool`, `int64_t`)
   and `muted_words.c` allocates and builds on every call. Platinum's Mac target
   is `-std=c89 -pedantic-errors`, so it cannot include them. The rules are the
   thing to port, not the code.

2. **CDN URLs.** `wf_bsky_cdn_url` rewrites a `cdn.bsky.app/img/<preset>/plain/
   <did>/<cid>[@format]` URL to a chosen preset and `@jpeg`, and refuses
   anything it does not understand. This is exactly what a Mac client needs to
   turn an avatar or post image into a small decodable JPEG. The header includes
   `wolfram/xrpc.h`, which pulls the C99-facing headers, so it is another port
   rather than an include.

3. **Image decode.** `wf_image_decode_rgba` (vendored stb_image plus a box
   filter) is real and is what Indigo uses. It still cannot be used here:
   compiling `wolfram/src/image.c` with Platinum's flags fails on
   `wolfram/include/wolfram/repo/cbor.h` (`-Wc99-extensions`: trailing comma in
   an enumerator list) and warns on `//` comments in `stb_image.h`, which
   `-Werror` turns fatal. The dependency chain is `image.h` → `util.h` →
   `agent.h` → `repo.h` → `repo/cbor.h`; the image module does not need the
   agent surface. This is a Wolfram packaging problem, not an image problem.

Wolfram also has `thread_typed.h`, but it only types the thread; it has no
flattener. The bridge's `flattenThread` (`bridge/src/domain/api.ts`) remains the
behavioural specification: 40 posts, 6 reply levels, 10 ancestors, blocked and
not-found nodes skipped, ancestors first with negative depth.

Platinum pins Wolfram **v0.36.2**, and that tag already contains `image.h`,
`muted_words.h` and `cdn.h`. So the pin does not block the image or muted-word
work; the C89 incompatibility does.

## Indigo

The closest sibling. `src/media/media_loader.c` uses
`wf_image_decode_rgba` with:

- `INDIGO_MEDIA_MAX_DIM 96` and a 128 px CDN avatar preset, so the decode is
  the size the UI draws;
- a 256 KiB download cap (`INDIGO_MEDIA_DOWNLOAD_MAX`);
- one worker thread, a 12-deep URL queue and four finished results;
- a separate unauthenticated client (`wf_http_get_public`) so no account token
  can reach an image host;
- `indigo_media_publish` refusing stale generations and over-budget pixels.

These are the right shapes for a small-memory client. The reuse is the design,
not the code: the loader is 3DS-specific (`Thread`, `LightLock`, 3DS logging).

## Cobalt

`src/ui/imagecache.c` decodes with SDL2_image, normalises to ARGB8888, box
downscales with premultiplied alpha, circle-masks avatars with a one-pixel
feather, and bounds the cache at 24 slots with two uploads a frame. The decoder
is devkitPro's SDL2_image; SDL does not exist for Mac OS 9, so only the
resampling and generation ideas are portable, and Wolfram's decoder already does
the box filter.

## Channel-blue

`source/render/image.c` decodes JPEG with libjpeg-turbo and PNG with libpng,
then uploads GX textures. The libraries are portable in principle but are not in
the pinned Retro68 image, and the file is tied to GX. Adopting it would mean
adding two new dependencies to the Mac build for a decoder Wolfram already has;
not worth it.

## Willow

Swift, SwiftUI and its own services (`ProfileService`, `ThreadService`,
`NotificationService`, `SessionPersistence`). It is useful for screen behaviour
and state organisation, and for nothing at the C level. No code was copied.

## Recommendations

1. **Muted words:** port Wolfram's rules into a C89 `macos9/muted_words.c` with
   the bridge's edge cases, and test them against the same vectors. Do not
   include Wolfram's C99 headers.
2. **CDN URLs:** port `wf_bsky_cdn_url`'s validated rewrite into the image
   module when images land; do not include `wolfram/cdn.h`.
3. **Images:** blocked on a C89-clean decoder. File an upstream Wolfram issue to
   split the image API from the agent/cbor dependency chain and make
   `stb_image.h` C89-clean (`/* */` only), or to publish a small
   `wolfram/image_c89.h`. Until then, keep the bridge image route.
4. **Thread flattening:** port the bridge's `flattenThread` rules; no sibling
   has a portable implementation.
5. **Profile, search, feeds, lists, compose:** the protocol shapes are the same
   ones the bridge already consumes through `@atproto/api`; the migration is
   request building and parsing in C89, not new behaviour.

## What is not verified

- No sibling was run here, on hardware or an emulator; their docs' claims are
  cited, not reproduced.
- Wolfram `sqrt`/stb behaviour on a PowerPC Mac is untested.
- The C89 compile check of Wolfram's image module was made with clang on macOS,
  not Retro68; the failure is in header syntax, so the conclusion is expected to
  hold, but the exact Retro68 diagnostics are unverified.
